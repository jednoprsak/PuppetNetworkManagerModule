## Description

You want to use our module because no one had written another module for using keyfiles yet (October 18, 2022) and we from Prague Academy of Physics computing farm geeks are the best underground team ever, but stop flexing. I hope that this module will be usable for you. The module installs NetworkManager, configures its config file, starts the service, creates keyfiles and pushes them inside NetworkManager via nmcli (and nmcli pushes them inside via dbus). It provides a few defined resources to create keyfiles for a connection (dhcp, static, ipv6, ipv4), bridge, bond and vlan, and a fallback defined resource for a user defined keyfile.

The module supports both Puppet and [OpenVox](https://voxpupuli.org/openvox/), the community fork of Puppet by Vox Pupuli, and is tested with both.


## Setup

### What networkmanager module affects

* The NetworkManager package, whose name is chosen by the OS family (Debian, RedHat, Arch Linux and Gentoo families are supported).
* The `NetworkManager.service` and `NetworkManager-wait-online.service` services (running and enabled, the wait-online one can be switched off).
* `/etc/NetworkManager/NetworkManager.conf`, which is fully managed (plugins, `no-auto-default`, `unmanaged-devices` and your own `additional_config`).
* `/etc/NetworkManager/system-connections/`, which holds one `<id>.nmconnection` keyfile (mode `0600`) per connection. With `erase_unmanaged_keyfiles => true` every keyfile in that directory which is not managed by Puppet is deleted.
* `/etc/resolv.conf`, only when `use_internal_resolv_conf` is set: it is then linked to the resolver file generated by NetworkManager (`true` or `'stub'`) or turned into a plain file (`false`).
* The state of the connections: after a keyfile changes, the module reloads the NetworkManager connections and activates or deactivates the connection with `nmcli` (through an `exec` that waits for the NetworkManager D-Bus service via `gdbus`). A connection with `state => 'down'` also gets its link set down with `ip link`.

### Setup Requirements

* Puppet `>= 4.9.2 < 9.0.0` or [OpenVox](https://voxpupuli.org/openvox/) `>= 7.0.0 < 9.0.0` (the community fork of Puppet by Vox Pupuli, tested in the CI as well).
* The `puppetlabs/stdlib` module `>= 5.2.0 < 11.0.0` (required: the module uses its IP address and MAC types and the `deep_merge` function).
* Exported resources (`storeconfigs`, usually PuppetDB): the connection activation is exported and collected by `networkmanager::reload`, so the catalog compilation needs a working exported resources backend.
* On the managed node: `nmcli` (installed with NetworkManager), `gdbus` (from GLib, present on all supported systems) and, for `state => 'down'`, `ip` (iproute2).

When you want to begin with NetworkManager, you need to be clever as devil, but

## Usage
```puppet

class {
  'networkmanager':
    erase_unmanaged_keyfiles => true,
    no_auto_default          => true;
}

networkmanager::ifc::connection {
  'z1':
    ensure         => present,
    mac_address    => '52:54:00:4d:2a:56',
    ipv4_method    => 'manual',
    ipv4_address   => '192.168.1.12/24,192.168.1.1',
    ipv4_dns       => '8.8.8.8;8.8.4.4;',
    ipv6_method    => 'manual',
    ipv6_dhcp_duid => 'auto',
    ipv6_address   => 'IPV6ADDRESS/PREFIX',
    ipv6_dns       => 'IPV6DNS1;IPV6DNS2;',
    ipv6_gateway   => 'IPV6GATEWAY';
}

networkmanager::ifc::bridge {
  'bridge1':
    ensure      => present,
    ipv6_method => 'ignore';
}

networkmanager::ifc::bridge::slave {
  'bridge1-slave':
    ensure      => present,
    mac_address => 'MM:AA:CC:MM:AA:CC', #here insert MAC address string.
    master      => 'bridge1';
}

networkmanager::ifc::bond {
  'bondmaster2':
    ensure            => present,
    ipv4_method       => 'auto',
    ipv6_method       => 'ignore',
    bond_mode         => 'balance-xor',
    additional_config => {
      bond => {
        miimon => '100',
      }
    };
}

networkmanager::ifc::bond::slave {
  'bondslaveens8':
    ensure      => present,
    mac_address => 'MAC_ADDRESS',
    master      => 'bondmaster2';
}

networkmanager::ifc::bond::slave {
  'bondslaveens9':
    ensure      => present,
    mac_address => 'MAC_ADDRESS',
    master      => 'bondmaster2';
}
```

## Connection id length
The `connection.id` parameter is limited by default to 15 characters, because it is by default used also as the interface name.
The interface name has an upper limit of 15 characters set by the kernel.
You can override this limit by setting `$networkmanager::max_length_of_connection_id` to the value you like, but then you need to set, where applicable, the `connection.interface-name` to something that is less than 16 characters long.
